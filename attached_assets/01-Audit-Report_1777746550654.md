# Muloo Deploy OS — Architect & Client-Portal Review

**Reviewer lens:** HubSpot delivery architect + client portal operations
**Date:** 2 May 2026
**Scope:** Full app walkthrough as the Muloo team persona (jarrud@muloo.co)
**Lens:** What does it feel like to actually run delivery in here, day after day?

---

## TL;DR (read this first)

Deploy OS is an unusually ambitious product. It tries to be the operating system for a HubSpot delivery shop — discovery, scoping, quoting, delivery, comms, retainers, financials, AI agents, the lot. The bones are good. The model (Engagement → Workstreams → Workbooks → Discovery → Plan → Delivery → Portal) genuinely fits how a HubSpot architecture business runs.

But three things are dragging it down right now:

1. **The information architecture is hiding half the product.** The sidebar has 19 items across five groupings, and the most strategically important sections (Automation, Operations, Admin) sit below the fold on a 13-inch laptop. New users will not discover Workbooks, Question Library, Implementation Templates, or Skeleton Key without being told.
2. **The Command Centre is doing too many jobs.** It is a morning brief, an inbox triage, a project status page, an AI composer, an automation log, and a news feed — all stacked vertically. The page scrolls forever and the most operationally important blocks (urgent quotes, projects in delivery, recent automation) are buried below empty-state setup prompts and an 8-card industry news feed.
3. **The project workspace has two competing navigation systems.** The "Workflow / Follow-on Work" stage rail at the top duplicates the tabs (Overview, Meetings, Discovery, Plan, Delivery, Comms, Portal) below — but with different labels and a different sequence. A delivery lead landing on a project should know exactly where to go next; right now they have to choose between two rails that mean roughly the same thing.

Fix those three and the rest of the product reads as polished. Leave them and the product feels cluttered no matter how good each individual screen is.

The good news: every fix is structural, not feature work. You don't need to build new things — you need to re-organise what's already there.

## 1. Information architecture — the landscape problem

### What you have today

Five logical groupings in the sidebar:

- (no group) — Command Centre, Inbox
- DELIVERY — Projects, Clients, Partners, Contacts
- SALES — Quotes, Products, Retainers, Invoices, Financials
- AUTOMATION — Portal Ops, Runs, Agents
- OPERATIONS — Workbooks, Question Library, Implementation Templates
- ADMIN — Skeleton key, Settings

That's 19 destinations.

### What's wrong

- **Below the fold.** On a standard 13-inch MacBook viewport, only two groups (DELIVERY and the start of SALES) are visible without scrolling the sidebar itself. New users will not know AUTOMATION, OPERATIONS or ADMIN exist. Anything you cannot see, you cannot use.
- **Operations is mis-grouped.** Workbooks, Question Library and Implementation Templates aren't really "operations" in the day-to-day sense — they are the **template library** that powers everything else. Calling that group OPERATIONS makes it sound like it's for administrators, when in fact your delivery leads need it constantly.
- **Sales is too long.** Five items (Quotes, Products, Retainers, Invoices, Financials) is more than any other group. Products is really an admin thing (catalogue management); it doesn't belong next to Quotes/Invoices in the daily workflow.
- **Inbox sits orphaned.** It's outside any group, but it's clearly a delivery surface. It should sit inside DELIVERY.
- **Two broken nav links.** `/portal-ops` returns a 404 from the sidebar, and `/implementation-templates` returns a 404 from the sidebar — though it works from the Settings cards as `/implementation-templates`. (The link on the sidebar is wired to a route that doesn't exist.) Broken links in primary navigation are a trust-killer.
- **Skeleton Key is in light mode** while every other page is dark mode. It's the only screen where the Muloo logo is missing too — the page just starts with the title. It looks like an unfinished prototype.

### The fix (recommended — see mockup file)

Reorganise into four clean groups, each visible without scrolling on a normal screen:

```
WORK            (the daily verbs)
  Command Centre
  Inbox
  Projects
  Clients
  Partners

SELL            (commercial pipeline)
  Quotes
  Retainers
  Invoices
  Financials

LIBRARY         (reusable assets — was OPERATIONS)
  Workbooks
  Question Library
  Implementation Templates
  Products
  Agents

ADMIN           (set up once, forget)
  Settings
  Skeleton Key
  Runs (move out of nav into Settings → Operations)
```

Move Contacts off the sidebar — it's a sub-view of Clients (the Contacts page itself even links back with "Go to Clients"). Keep it as a tab inside Clients.

Move Runs into Settings → Operations (or under a dropdown inside Agents) — it's a debug/observability surface, not a daily destination.

Move Products into LIBRARY because it's catalogue management — you're not "selling products" from here, you're maintaining the menu that gets pulled into quotes.

Result: 14 nav items in 4 cleanly named groups, all visible on a 13-inch screen.

## 2. Command Centre — the front door

### What you have today

Seven distinct content blocks stacked vertically on a single page:

1. Greeting + URGENT alert (e.g. "URGENT: Quotes Awaiting Approval")
2. Five top-line stats (Live projects, In delivery, Awaiting approval, Blocked external, Overdue invoices)
3. Three Google integration columns (Email watchlists, Calendar today, Private Tasks) — mostly empty / setup prompts
4. AI-assisted email composer
5. Projects in delivery panel (currently empty)
6. Recent automation feed (with FAILED runs prominently visible)
7. Daily Signal — 8-card industry news feed

### What's wrong

- **Wrong job, wrong order.** A command centre is meant to answer one question: "what needs my attention right now?" The first thing Jarrud sees that needs action is the URGENT banner — good. But the stats below it use inconsistent terminology ("Live projects 5" vs "In delivery 0") that contradicts what other pages call the same number. The Projects page calls them "Total Projects 5 / In Execution 0" — same numbers, different words.
- **Setup prompts mixed with live data.** The Google integration columns are mostly placeholder text ("Add the exact Gmail label…", "Add Google Workspace credentials once…"). On a real working day this is visual noise. Setup prompts belong in onboarding, not on the daily home screen.
- **Negative trust signals are surfaced too prominently.** The Recent Automation panel shows three FAILED workflow runs in a row at the top of its list. For a tool you're trying to position as a calm operating system, the home page leading with red error states is the wrong vibe.
- **Daily Signal is 80% of the screen real estate.** The industry news feed (8 cards, scrolling vertically) takes more vertical space than every operational element combined. A daily news ribbon is a nice-to-have at best — it doesn't deserve the bottom half of the home page.
- **No "what's next" intelligence.** There's no "today's three things" surface. The user has to read every panel and decide for themselves what matters.

### The fix (recommended — see mockup file)

Rebuild the Command Centre around three sections, top-to-bottom:

1. **What needs you (the first screen, no scroll).**
   A single horizontal strip of 4–5 attention items, each one a clickable card that takes you straight to the action:
   - "2 quotes awaiting approval" → Quotes filtered to Sent
   - "2 projects blocked on client" → Projects filtered to Awaiting client
   - "0 overdue invoices" (green / dismissible)
   - "82 unanswered discovery questions across Magnisol" → Magnisol discovery
   - "1 portal disconnected — Magnisol" → reconnect flow

2. **Live work (mid-screen).**
   - Projects in delivery (table, only when there's actual data)
   - Today's calendar (compact, single column, only events visible — not setup prompt)
   - Tasks (compact, only items count + add field)

3. **Background (collapsible, default closed).**
   - Daily Signal news feed (collapsed accordion, "8 new today")
   - AI email composer (move to its own surface — it's not a home-screen widget, it's a tool)
   - Recent automation (collapsed, only show failures with a count badge)

Replace the empty states / setup prompts with a single "Connect your tools" card that links to Settings if the integration is missing, and disappears once connected.

## 3. Project workspace — the dual-navigation problem

### What you have today

A project (e.g. Magnisol HubSpot and Website Delivery) opens with two distinct navigation rails stacked on top of each other:

**Rail 1 (top): Workflow → Follow-on Work**
- CONTEXT: Project Summary, Prepare, Inputs
- DIAGNOSE: Portal Audit
- PLAN: Blueprint, Scope & Approval
- DELIVER: Change Mgmt, Delivery Board

**Rail 2 (below the title): Tabs**
- Overview, Meetings, Access & Sharing, Discovery, Plan, Delivery, Comms, Portal

Below those: a row of six "Next Actions" buttons (Add latest meeting, Create workbook, Add contributor, Add resource, Open client portal, Generate next actions).

### What's wrong

- **The two rails overlap.** Project Summary ≈ Overview, Blueprint ≈ Plan, Delivery Board ≈ Delivery, Change Mgmt ≈ Delivery. It's the same content reachable through different doors with different names. This is exactly the kind of thing that makes a product feel "cluttered and confusing" — your words.
- **Three rows of navigation chrome before any actual content.** Workflow rail (4 sub-groups, 9 buttons) + tabs (8) + next-actions (6) = 23 navigation targets before you see a single thing about the project. That's a serious cognitive load every time you open a project.
- **The Workflow rail's purpose is unclear.** It seems to want to be the canonical phase model (Context → Diagnose → Plan → Deliver) but then the tabs use a different model (Overview → Meetings → Access & Sharing → Discovery → Plan → Delivery → Comms → Portal). Pick one.
- **"Next Actions" is misleadingly generic.** Those six buttons are global utilities, not next-best-actions for this specific project. A real "next best action" engine would say "Magnisol's Discovery Session 2 is unanswered — chase Tara" or "the Portal Audit has been open for 11 days". Right now they're just shortcuts in a row.
- **The Edit/Archive/Delete actions on the Projects list are dangerous.** All four actions sit inline, in colour, on every row. One mis-click on Delete in a list and a project's gone. (See list-design fix below.)

### The fix (recommended — see mockup file)

**Collapse to ONE navigation rail.** The tabs win — they're cleaner and they reflect the operational sequence. Bin the Workflow / Follow-on Work rail entirely, OR re-cast it as a phase indicator (a slim status bar showing "you are in PLAN, 60% through") — not as nav.

Then re-order the tabs to match the actual lifecycle:

```
Overview → Discovery → Plan → Delivery → Change → Comms → Portal → Settings
```

Move Meetings under Comms (meetings are a comms artefact, not a nav peer).
Move Access & Sharing under Settings (it's admin, not daily work).

Replace the generic "Next Actions" row with a real next-best-action component:

- Driven by data (open questions, blocked tasks, unread comms, expiring NDAs).
- Maximum 3 cards.
- Each card has one clear CTA.
- Empty state: "Nothing requires you right now. Last activity was 4 hours ago."

On the Projects list, collapse the per-row actions into a single "•••" overflow. Move View into a click on the project title (the standard pattern). Hide Delete inside an "Are you sure" double-confirm modal.

## 4. Discovery, workbooks and the question library

### What you have today

- Each project has 4 fixed Q&A sessions (Business & Goals, Current State, Future State Design, Scope & Handover).
- Each project also has multiple workbooks attached (Sales & Marketing, Service & Reporting, HubSpot + Website Discovery, Tech Stack & Cost), each with multiple visibility states (Internal only, Contributor access, Client champion review, Client portal visible).
- The Workbooks (templates) page is empty — 0 templates — even though projects clearly have workbooks attached.
- The Question Library has 82 questions across 13 categories, with a yellow warning banner: "Categorisation health: 82 of 82 questions use categories outside the canonical list."

### What's wrong

- **Two parallel "what we ask" systems.** The 4 Q&A sessions and the workbooks both collect structured discovery answers. It's not obvious to a delivery lead which goes where, or what's required vs optional.
- **Workbook templates page is empty but workbooks exist.** Discovery says "start from a reusable template managed in Operations → Workbooks" — but there are no templates there. Either the templates page hasn't been seeded, or the workbooks attached to projects came from somewhere else (the question library?). Either way it's confusing.
- **Workbook visibility is overloaded.** Four visibility states (Internal only, Contributor access, Client champion review, Client portal visible) is one or two too many. In practice teams want: "internal only" or "client can see" — maybe with one extra "draft for review by champion only". The four-state model invites mistakes (you accidentally share an internal draft).
- **Question Library categorisation is broken at scale.** 82 of 82 questions are mis-categorised, by the system's own warning. That's not a small data quality issue, that's the entire library out of alignment with the canonical category list. This will quietly degrade every workbook generated from it.
- **0/82 unanswered on the project overview** is a silent number. There's no "due by" date, no owner, no chase mechanism. Discovery rots.

### The fix (recommended)

- **Pick ONE primary discovery model.** Options:
  - **(Recommended)** Make Workbooks the primary surface; demote Q&A sessions to "discovery rituals" inside the workbook flow. A workbook = a structured questionnaire with sections, owners and visibility.
  - Or make Sessions primary and treat workbooks as appendices.
- **Seed Implementation Templates and Workbook Templates as part of onboarding.** Every new workspace should boot with the canonical Muloo template set already installed. Empty libraries make the product feel half-built even when the underlying data model is right.
- **Collapse visibility to 3 states max:** Internal, Contributor, Client. Add a single per-question "client visible?" toggle if you need finer control inside a workbook.
- **Fix the question library.** Run a one-off re-categorisation pass against the canonical list, then enforce the canonical list in the New Question form (no free-text categories).
- **Add chase mechanics to discovery.** Each unanswered question gets an owner + a due date. Surface "questions overdue" on the project Overview AND the Command Centre.

## 5. AI agents and automation — the most undercooked surface

### What you have today

- AGENTS page = a vertically stacked list of full-form-per-agent. Each agent has Name, Purpose, Service family, Provider, Model, Trigger, Approval, Allowed actions, System prompt, Active toggle, Save Agent button. They're all rendered open at once. There are duplicate cards (two "Scope & Commercial Agent" entries visible in the same list).
- RUNS = a unified execution feed showing workflow + agent runs across all projects. Many show FAILED status without obvious follow-up.
- Agents referenced in projects: Discovery Structuring, Delivery Planner, Scope & Commercial, Portal Audit. Their outputs feed the Project workspace's "Agent summary" (currently empty everywhere I checked).

### What's wrong

- **The Agents page is an editor with no list.** You can edit every agent, but you can't see them at a glance, search them, filter by service family, see when each last ran, or which ones are turned off. It's a config screen masquerading as a directory.
- **No accountability for agent output.** The project Overview has "Agent summary — No executive summary saved yet" but there's no "run this agent now" button visible from the Overview, no "last run by" stamp, no "approve / reject" surface.
- **FAILED runs have no triage path.** The Runs feed shows failures but there's no "retry", no "what failed", no "ack this".
- **Duplicate agents in the catalogue.** Looks like the seed data has been re-applied without de-duplication.
- **Approval mode is set to "Review required" on everything but it's unclear where the review queue lives.** If 5 agents all output drafts that need review, where do those reviews surface?

### The fix (recommended — see mockup file)

- **Rebuild Agents as a directory (table) with inline edit, not a stack of forms.**
  Columns: Name, Purpose, Service family, Trigger, Last run, Status, Active (toggle), Edit. Click a row to open the editor in a side-panel or modal.
- **Add an Agent Run Queue (or merge into Runs):** items needing human review (the "Review required" outputs) sit here with an Approve / Edit / Reject action.
- **Surface "Run this agent" CTAs from the Project workspace** wherever agent output is expected (Agent summary, Blueprint status, Discovery sessions). Show a freshness stamp ("last run 4d ago").
- **De-duplicate seed data** and add a uniqueness constraint on agent name + service family.
- **Add a failure recovery loop:** every FAILED run gets a Retry button and a one-line failure reason. If three retries fail, page the operator.

## 6. Delivery, change management and handover

### What you have today

The project's Delivery tab shows a 6-column kanban (Backlog, Todo, In Progress, Waiting on Client, Blocked, Done) — currently all 0. Below that, a Change Management panel ("Use the change-management workspace to review scope changes once the approved plan starts moving") with a single View Changes link.

### What's wrong

- **Delivery is empty for active projects.** The Magnisol project is marked ACTIVE but has 0 tasks across all six columns. Either tasks live somewhere else (Miro? HubSpot? a Google Doc?), or the model wants tasks but they're not being captured. The Project Overview shows "0 tasks linked" against each workstream, which suggests the latter.
- **No handover artefact.** Scope & Handover is one of the four discovery sessions, but the project workspace has no "Handover document" surface, no "what gets given to the client at end of project", no proof-of-completion archive.
- **Change Management is a single link.** No visible inbox of pending changes, no approval flow visible at the project level, no diff view of "what was scoped vs what was delivered".
- **No retainer hand-off.** When an implementation finishes, there's no one-click "convert to ongoing retainer" or "create handover doc". Retainers and Projects are completely disconnected as systems.
- **No project closure ritual.** No "complete project" wizard that produces: handover doc, lessons learned, NPS, archived workbooks, retainer kick-off if applicable.

### The fix (recommended)

- **Make Delivery the first-class surface for tasks.** Either seed it from the workstreams in the Plan tab, or integrate with whatever today's actual task system is (HubSpot tickets? Linear?). Right now it's an empty kanban that signals "not used".
- **Add a Handover surface.** New tab (or a section under Portal): a structured handover document template that pulls in scope, blueprint, workbook outputs, decisions log, training links, Loom embeds, support process, retainer link. One click to share with the client.
- **Promote Change Management to a tab** with: pending changes (from inbox), approved changes, rejected changes, current scope diff. Right now it's buried under Delivery.
- **Build a "Close project" wizard.** Triggered when you set status to Complete: prompts handover doc, captures NPS, archives workbooks, optionally creates a retainer.
- **Link projects ↔ retainers.** A project that finishes should ask: "convert to retainer?". A retainer should show: "born from project X". Today they're parallel universes.

## 7. Sales pipeline — Quotes, Products, Retainers, Invoices, Financials

### What's working

- **Quotes** is clean: filterable by status (Draft, Sent, Approved, Won, Lost, Archived, Superseded), searchable, with a clear primary CTA. The status pill model is good.
- **Retainers** has a sensible split-screen create-on-the-right pattern.
- **Financials** dashboard has the right metrics in the right order (Pipeline, Approved, Won this month, Monthly recurring) plus Won-by-month chart and Quote funnel.

### What's not

- **Quotes has a mystery "?" filter pill.** No tooltip, no label. Either it's a feature flag, an unfinished status, or a help control. Either way it's noise.
- **Products is light on metadata.** No supplier / cost / margin fields visible (couldn't load fully but the page chrome suggests basic name+price+category). For a product catalogue that feeds quotes and retainers, you want margin awareness baked in.
- **Invoices empty state is weak.** "No invoices yet. Invoices appear here once you record a retainer block or approve a top-up. Once Xero is connected, drafts flow there too." The CTA is "Open retainers" — but this should also offer "Connect Xero" if Xero isn't connected.
- **Financials has no time filter.** "Last 6 months" is hard-coded. No "This year", "QTD", "compare to prior period". For a financials dashboard that's a pretty thin set.
- **No ARR / revenue forecast.** Pipeline and recurring are shown, but the natural next question — "what does the next 90 days look like?" — isn't answered.

### The fix (recommended)

- **Remove or label the `?` filter.** If it's "Other", call it Other. If it's broken, ship a fix.
- **Add cost + margin fields to Products** so the Quote builder can show margin in real time.
- **Invoices empty state** should detect Xero connection state and offer the right CTA.
- **Add a date-range picker to Financials** with This Quarter / This Year / Custom presets.
- **Add a 90-day forecast block to Financials** = recurring + weighted pipeline (assigns close probability per status).

### What you have today

- **Settings** is a clean 6-card grid (Workspace, Team, Providers, AI Routing, Email, Products, Implementation Templates). Decent IA.
- **Skeleton Key** is the operator-mode tool to log into any client portal as `skeleton@muloo.internal` for 60 minutes. Useful pattern.
- **Sidebar items that 404:** Portal Ops, Implementation Templates (works from Settings, broken from sidebar)

### What's wrong

- **Skeleton Key is light mode.** Every other page is dark. The Muloo logo isn't even on the page. It looks like an unfinished prototype.
- **Settings doesn't surface integration health.** No "Xero: connected", "HubSpot: 4/5 portals connected", "Email sender: verified" at a glance. You have to drill into each card to see status.
- **No Team management visible from a top-level view.** Settings → Team exists but I couldn't tell from the cards how many users you have, who's an admin, who's a delivery lead. For a delivery shop, "who's on what" is operational.
- **No global activity log.** With Skeleton Key impersonation in play, you really want an audit log: who accessed which client portal, when, for how long. (Your Master Queue does include this — Hardening row 26.)

### The fix (recommended)

- **Bring Skeleton Key into the dark theme** and add the Muloo logo + breadcrumb so it visibly belongs to the same product.
- **Add an integration health strip to Settings → Overview** with one-line status per integration, colour-coded, with a Reconnect button when relevant.
- **Surface Team on the Settings overview** as a card with member count, last invite, role split.
- **Audit log page** (already on your Master Queue — keep it).
- **Fix the broken sidebar links** before anything else this week. Quick win.

## 10. Templates audit — do they make sense?

Three template surfaces exist:

| Surface | Purpose | State today |
|---|---|---|
| **Workbooks** (Operations → Workbooks) | Reusable workbook templates per project type | **Empty (0 templates)** despite projects using workbooks |
| **Question Library** (Operations) | Master bank of discovery questions | 82 questions, but **all 82 are mis-categorised** by the system's own warning |
| **Implementation Templates** (Settings) | Repeatable delivery patterns (theme installs, onboarding, migrations) | **404 from sidebar**, works from Settings |

**Verdict:** the model is right. The execution is weak.

- The model "Question library → Workbook templates → Project workbooks" mirrors how a real HubSpot delivery shop should industrialise its discovery process. Keep it.
- But none of the libraries are populated, the categories are broken, and the link is broken. So even though the architecture is correct, a new user opens these screens and concludes "this isn't real yet".

**Fix:** seed a canonical Muloo template set as part of every workspace. Without a starter library, templates stay an empty promise.

## 11. Onboarding a new client — end-to-end walkthrough

I traced what happens when Muloo wins a new client and starts a project.

### What works
- The "Create new project" wizard is a clean 3-step flow (Project + Client → Brief → Review).
- Three engagement containers (Discovery-led implementation / Standalone quote job / HubSpot Optimisation / Revamp) is the right level of choice — covers the realistic shapes of work.
- Required fields (project name, client name, champion first/last/email) are clearly marked.

### What doesn't
- **Step 1 mixes "create client" and "create project" without checking if the client exists.** If Magnisol already exists in the workspace, the form should auto-complete from existing client data, not ask me to re-enter Industry, Region, LinkedIn, Facebook, Instagram, X, YouTube. Right now if you create the project from the Clients page using "+ New Project" you can pre-pick a client; from elsewhere, it's a fresh form.
- **Champion email is captured but no invite is auto-sent.** A champion isn't really a champion until they can log in. The wizard should offer "send portal invite now" with a one-line preview message.
- **No "what happens next?" preview at the end of step 3.** After Review/Create, the project lands you in the project workspace cold. A 30-second checklist ("Now do these 4 things to get the project going") would massively help.
- **No portal auto-creation visible during the wizard.** The Magnisol portal status is "Disconnected" days after the project was created. Either the portal should be auto-provisioned and connected on project create (the Master Queue's Improvement 5), or the wizard should explicitly say "connect a portal now".

### Recommended onboarding flow (revised)

```
Step 1: Engagement type + Client
  - Pick engagement
  - Pick existing client OR start new client (one path each)
  - If new: minimal fields only (name, champion, email, website)

Step 2: Brief
  - Auto-prefill what we can from website (logo, social, region) via existing AI agent
  - Project name, owner, hubs in scope, target start

Step 3: Review + Provision
  - Confirm details
  - Create project + auto-provision portal + send champion invite + queue Discovery Session 1 reminder
  - Land on project Overview with a "5 things to do this week" checklist
```
