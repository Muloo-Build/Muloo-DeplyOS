**Companion to:** 01-Audit-Report.md
**Date:** 2 May 2026
**Format:** Phased, ticketed, with effort, dependencies, and acceptance criteria

This plan is layered ON TOP of your existing Master Queue. It does not replace it. Items below are sequenced for fastest visible impact on the "cluttered and confusing" problem you raised.

---

## Sequencing rationale

Three goals, in order:

1. **This week — kill the "feels half-built" signals.** Quick wins that change first impressions: broken links, light-mode admin page, dangerous inline destructive actions. Sub-day each.
2. **Weeks 1–2 — fix the landscape.** Structural changes to navigation and the Command Centre that resolve the "cluttered" feedback. These are the highest-leverage UX changes in the entire backlog.
3. **Weeks 3–6 — fix the meat.** Project workspace, agents, discovery model, onboarding wizard. Where the real product depth lives.

A 6-week plan that takes the product from "looks like a great prototype" to "feels like a real operating system."

## Phase 1 — Landscape fix (Week 1, 4–5 days)

The goal here: a new user can find every primary surface in the app without scrolling, and the home page tells them what to do today.

### 1.1 Sidebar restructure (M)

Reorganise into 4 groups, max 5 items per group, all visible above the fold on a 13-inch viewport:

```
WORK
  Command Centre, Inbox, Projects, Clients, Partners

SELL
  Quotes, Retainers, Invoices, Financials

LIBRARY
  Workbooks, Question Library, Implementation Templates, Products, Agents

ADMIN
  Settings, Skeleton Key
```

- Move **Contacts** off sidebar → tab inside Clients page
- Move **Runs** off sidebar → page under Settings → Operations (or as a tab inside Agents)
- Move **Products** from SALES → LIBRARY (it's catalogue, not pipeline)
- Move **Agents** from AUTOMATION → LIBRARY (an agent is a reusable asset)
- Rename **OPERATIONS** group → **LIBRARY** (it's not "operations", it's reusable assets)

Acceptance:
- Sidebar shows 4 groups + 14 items, no scrolling needed at 1440×900.
- All previous URLs continue to work (set up redirects if Contacts/Runs move).
- Visual hierarchy: each group label slightly muted, items same weight.

**Dependencies:** none. Do first.

### 1.2 Command Centre rebuild (M)

Three sections, not seven. New top-to-bottom:

**Section A — "What needs you" (always above the fold)**
- Horizontal strip of 3–5 attention cards.
- Each card = one count + one label + one CTA.
- Driven by a single rules engine: quotes awaiting approval, projects blocked on client, overdue invoices, unanswered discovery questions, disconnected portals.
- If there's nothing — say so explicitly: "Nothing requires you right now. Coast."

**Section B — Live work**
- Projects in delivery (table, hidden when 0)
- Today (compact: calendar today + tasks today, only when there's content)

**Section C — Background (collapsible, default closed)**
- Daily Signal (collapsed accordion with count badge)
- Recent automation (collapsed, only failures with badge)

Move the AI email composer OUT of the Command Centre. It's a tool, not a home-screen widget. Give it its own page or surface it from the project Comms tab where it already lives.

Replace empty integration prompts (Gmail, Calendar, Tasks) with a single "Set up integrations" card that disappears once connected.

Acceptance:
- First screen above the fold = "What needs you" + the greeting.
- No empty-state placeholder text on the home page (other than the consolidated setup card).
- Scrolling reveals live work, then collapsed background.

**Dependencies:** none. Independent of 1.1.

## Phase 2 — Project workspace overhaul (Week 2, 3–4 days)

### 2.1 Kill the dual navigation (M)

Two paths:
- **Recommended:** delete the Workflow / Follow-on Work top rail entirely. Re-cast as a slim phase indicator showing where the project is in its lifecycle (Discovery → Plan → Delivery → Handover, with a progress dot).
- **Or:** delete the tabs and keep the Workflow rail. (Less recommended — tabs are more conventional.)

### 2.2 Re-order tabs to lifecycle order (S)

```
Overview · Discovery · Plan · Delivery · Change · Comms · Portal · Settings
```

- Move **Meetings** under Comms (sub-tab or section).
- Move **Access & Sharing** under Settings.
- New tab: **Change** (today's Change Management lives buried in Delivery).

### 2.3 Real next-best-actions (M)

Replace the "Next Actions" row of generic shortcut buttons with a real engine:

- Max 3 cards.
- Driven by data: open questions over due, blocked tasks, unread comms, expiring NDAs, Portal disconnected, Agent summary stale.
- Each card has a single CTA.
- Empty state: "Nothing requires you right now. Last activity 4 hours ago."

Move the old shortcut buttons (Add latest meeting, Create workbook, Add contributor, Add resource, Open client portal, Generate next actions) into a "+ Quick add" dropdown in the project header. Keep the access; lose the visual weight.

Acceptance:
- A project page opens with a clean header → phase indicator → 3 next-best-action cards → main content.
- No more "Workflow" top rail.
- Tabs are in lifecycle order.

**Dependencies:** none.

## Phase 3 — Agents and Runs rebuild (Week 3, 3–4 days)

### 3.1 Agents directory (M)

Replace the stack-of-forms page with a directory table:

| Name | Purpose | Service family | Trigger | Last run | Status | Active | |
|---|---|---|---|---|---|---|---|

Click row → side panel opens with full edit form.
Add: search, filter by service family, filter by status (active/inactive/failed-recently).

### 3.2 De-duplicate seed data (XS)

Add a uniqueness constraint on (agent name + service family) and clean up the duplicate "Scope & Commercial Agent" entries.

### 3.3 Run this agent (S)

Surface "Run now" CTAs from the Project workspace where agent output is expected:
- Project Overview → Agent summary card → "Refresh AI summary" already exists, good. Add similar to Blueprint (Generate blueprint), to Discovery (Run discovery structuring).

Add a freshness stamp to each generated artefact ("Last generated 4d ago by Discovery Structuring Agent").

### 3.4 Run review queue (M)

If an agent's approval mode is "Review required", its output should land in a queue, not just save silently. Build a Review Queue page (or a tab inside Runs):

- List of items pending review, oldest first
- Each item: agent name, project, output preview, Approve / Edit / Reject
- Approving = publishes the output to where it belongs
- Rejecting = sends it back with a note

### 3.5 Failure recovery (S)

Every FAILED run gets:
- One-line failure reason
- Retry button (capped at 3 retries before paging operator)
- Link to full logs

Acceptance:
- Agents page is a sortable, searchable table; no more endless scroll of forms.
- Review queue exists and is wired up.
- Failed runs are recoverable with one click.

**Dependencies:** none, but ideally after Phase 1 sidebar move (so Agents lives in Library).

## Phase 4 — Discovery model + template seed (Week 4, 3–5 days)

### 4.1 Pick ONE primary discovery model (M)

Recommended: **Workbooks become the primary surface.** Sessions become a discovery ritual layer (kick-off, mid-point check, future-state, scope sign-off) that *use* workbooks rather than competing with them.

Rework the Discovery tab to lead with workbooks; sessions appear as a secondary block ("Ritual sessions: 4 planned").

### 4.2 Collapse workbook visibility to 3 states (S)

From: Internal only · Contributor access · Client champion review · Client portal visible
To: Internal · Contributor · Client

Add a per-question override "show in client portal?" if you need finer control.

### 4.3 Seed the canonical Muloo template library (M)

Every new workspace boots with:
- 3–5 workbook templates (Sales+Marketing discovery, Service+Reporting discovery, Tech Stack discovery, Website+Content discovery, Implementation discovery)
- 5–10 implementation templates (Theme install, Onboarding, Migration, Integration build, RevOps audit)
- Question Library categorised against the canonical category list

This is content work, not engineering. Block out a half day with the team to do it.

### 4.4 Fix Question Library categorisation (S)

The "Categorisation health: 82 of 82 questions use categories outside the canonical list" warning needs to go away.

- One-off re-categorisation pass against the canonical list.
- Constrain the New Question form to the canonical list (no free-text categories).
- Display a healthy state: "All 82 questions categorised against the canonical list."

### 4.5 Discovery chase mechanics (M)

Each unanswered question gets:
- An owner (default: client champion)
- A due date (default: 5 business days after assignment)
- Surface "X questions overdue" on the Project Overview AND the Command Centre's "What needs you" strip

Acceptance:
- Discovery tab leads with workbooks, sessions secondary.
- Workbook visibility = 3 clear states.
- Workbooks page has 3+ seeded templates.
- Implementation Templates page has 5+ seeded templates.
- Question Library categorisation health = green.
- Overdue discovery questions surface on Project Overview and Command Centre.

**Dependencies:** Phase 1.2 (Command Centre attention strip needs a target).

## Phase 5 — Onboarding wizard revision (Week 5, 2–3 days)

### 5.1 Existing-client check in step 1 (S)

If user types a client name that already exists, prompt: "Magnisol already exists. Use existing client and add a new project?"
If yes, skip all the duplicate Industry / Region / Social fields.

### 5.2 Auto-provision portal on project create (S)

Hook into the existing portal model. When a project is created:
- Auto-provision a portal under the client
- Auto-add the champion as a portal user
- Send champion invite email (with a preview shown to the operator before send)

(This is roughly your Master Queue Improvement 5; flesh out with wizard integration.)

### 5.3 "Now do these 5 things" landing checklist (S)

After step 3, instead of dumping the user into a cold project workspace, land them on a 5-item checklist:
- Run Discovery Structuring Agent (queues up)
- Schedule Discovery Session 1
- Add contributors
- Generate Blueprint draft
- Send champion welcome email

Each item links to the right surface. Items tick off as completed.

### 5.4 Auto-prefill from website AI (S — depends on existing agent)

Use the existing prepare/research agent to auto-fill Industry, Logo URL, Social URLs from the primary website. Saves the operator 5+ minutes per new project.

Acceptance:
- Creating a new project for an existing client takes 4 fields max.
- Champion gets a portal invite within 60s of project creation.
- Operator lands on a checklist, not a cold workspace.

**Dependencies:** Phase 4 (Implementation Templates seeded so checklist items map to real artefacts).

## Phase 6 — Delivery and handover (Week 6, 4–5 days)

### 6.1 Make Delivery the first-class task surface (M)

Wire the Delivery kanban to actually receive tasks:
- Tasks auto-created from workstream items in Plan tab
- Tasks pull-able from Implementation Templates
- Tasks linkable to HubSpot tickets (for HubSpot-side work)

### 6.2 Promote Change Management to its own tab (S)

Move out of Delivery. New tab structure:
- Pending changes (from Inbox)
- Approved changes (audit trail)
- Rejected changes (with reasons)
- Scope diff (current vs original)

### 6.3 Handover surface (M)

New tab or new section under Portal: "Handover".
- Structured doc template
- Auto-pulls scope, blueprint, decisions log, workbook outputs, training links
- One-click "share with client" → goes to portal
- Doubles as the project closure artefact

### 6.4 "Close project" wizard (M)

Triggered when status set to Complete:
- Confirm handover doc generated
- Capture NPS (1–10 + free text)
- Archive workbooks (not delete)
- Optional: "Convert to retainer?" with one-click setup

### 6.5 Project ↔ Retainer link (S)

- A project that finishes can spawn a retainer (pre-filled from project context)
- A retainer shows "Born from project: X"
- A retainer can spawn a follow-on project

Acceptance:
- Delivery board has tasks for live projects (no more empty kanbans on ACTIVE projects).
- Change Management is a tab.
- Setting a project to Complete walks the user through a wizard, not just a status change.
- Projects and retainers are visibly linked.

**Dependencies:** Phase 4 (Implementation Templates feed tasks).

## Recommendation: which sequence

If you can only do one phase a week and want maximum visible impact:

- **Week 1:** Phase 0 (1.5 days) + Phase 1.1 sidebar (1 day) + Phase 1.2 Command Centre (2 days). Done.
- **Week 2:** Phase 2 project workspace.
- **Week 3:** Phase 3 agents.
- **Week 4:** Phase 4 discovery model + template seed.
- **Week 5:** Phase 5 onboarding wizard.
- **Week 6:** Phase 6 delivery and handover.
- **Week 7+:** Phase 7 sales polish, then Phase 8 client portal audit.

If you want maximum *commercial* impact instead of UX impact:

- **Week 1:** Phase 0 + Phase 5 onboarding wizard rev. (Faster client onboarding = more clients in faster.)
- **Week 2:** Phase 4 templates seed. (Once a client is in, faster delivery start.)
- **Week 3:** Phase 6 handover. (Faster close = faster retainer conversion.)
- **Week 4:** Phase 1 + Phase 2 (the UX cleanup).
- **Week 5+:** rest.

Pick the lens that matches what's driving you right now — polish for trust, or speed for revenue. They're both right answers.
